# Верифікація корпусу

Це редакторський журнал якості корпусу ТРЯСЦІ. Він потрібен, щоб не змішувати три різні речі:

1. форму, зафіксовану у фольклорному, літературному або словниковому шарі;
2. природний словотвір чи граматичну форму;
3. сучасну інженерну адаптацію.

## Поточний статус

- 100 із 100 рядків проходять машинний аудит.
- Усі записи мають форму, значення, рівень, джерельний код і стан A/B/C.
- Кожен запис має один із двох статусів цитування: `exact_anchor` або `candidate`.
- `exact_anchor` містить конкретну сторінку або зафіксований словниковий/фразеологічний запис; `candidate` свідомо не видається за дослівну цитату.
- Після редакторського проходу 1.1 розподіл становить 95 `exact_anchor` / `accepted` і 5 `candidate`.
- У runtime-пул за замовчуванням потрапляють лише 95 `accepted`-записів із `exact_anchor`; 5 кандидатів залишаються лише в повному аудиті `records`.
- V1-набір містить 15 anchors у `evals/verified-anchors-v1.json`; 1.1-набір додає ще 5 у `evals/verified-anchors-1.1.json`.
- Усі 10 frozen candidates із `evals/v1-candidate-freeze.json` мають явне рішення у `evals/candidate-decisions-1.1.json`.

## Редакторський прохід 1.1

Підвищено або замінено на exact-anchor форму:

- `йобнулося` → `promote`;
- `ебашити` → `ібошити` (`replace`);
- `ебашить` → `ібошить` (`replace`);
- `ебанутися` → `їбанутися` (`replace`);
- `довбодятел` → `promote`.

Свідомо залишено `candidate`:

- `заїбаний` — словотвір природний, але окремого сильного exact anchor недостатньо;
- `наїбка` — сильного українського exact anchor не знайдено;
- `наїбнутися` — неформальних вживань недостатньо для поточного стандарту;
- `прихачити` — інженерна адаптація без окремої сильної фіксації;
- `стоїть колом` — джерела фіксують ширшу фразеологічну конструкцію, а не самостійну технічну форму.

## Behavioral regression gate

`evals/behavior-policy.json` і `scripts/validate-behavior.mjs` машинно фіксують межі поведінки:

- `normal` не використовує стилізовану лексику;
- `lite` не допускає сильні register-форми;
- `full` та `ultra` підкоряються intensity calibration;
- public output, security та irreversible operations лишаються чистими;
- лайка не спрямовується на користувача;
- candidate не може використовуватися як runtime-форма.

## Що вважається достатньою перевіркою

### Source layer

Форма має зрозумілий джерельний напрям: словниковий, фольклорний або літературний. Це достатньо для робочого корпусу, але не для висновку про найдавнішу фіксацію чи етимологію.

### Exact anchor

Для форми збережено пряме посилання на сторінку, словникову статтю, конкретний запис або явне словникове перехресне посилання. Написання ключа exact anchor має відповідати формі корпусу.

### Adaptation

Форма або значення пристосовані до інженерного контексту. Такий запис не видається за автентичну цитату й не переходить до runtime без exact anchor.

## Робочий процес

1. Запустити `npm test`.
2. Для нового запису додати форму в Markdown-корпус.
3. Призначити джерельний код і стан A/B/C.
4. Якщо є точна сторінка — додати її до відповідного `evals/verified-anchors-*.json`.
5. Для перегляду frozen candidate записати рішення в `evals/candidate-decisions-1.1.json`.
6. Повторно запустити `npm test` і закомітити перегенерований `korpus.json` без drift.
7. Перевірити behavioral fixtures: public/security/user-target/intensity/mode isolation.

## Заборонені скорочення шляху

- Не позначати сучасну адаптацію як літературну цитату.
- Не називати форму загальновживаною лише тому, що вона звучить природно.
- Не підвищувати дериват лише тому, що підтверджена його базова лема.
- Не робити етимологічних висновків із самого звучання.
- Не додавати регіон без джерельної підстави.
